# How this register works

*Default charter. For now it is changed by the people running the register.*

## What this register is for

This is where we keep track of questions we want to answer together: decisions we need to make, and open questions that matter to the group. It doesn't host discussions. Each question links to the place where it's being worked on.

## Who can do what

- Anyone with the edit link can add questions, adopt them, attach processes, set criteria, object and confirm resolutions.
- Anyone with the view link can read everything.
- Display names are not verified. Please use the name people know you by.
- Everything that changes is recorded in the activity log, and the log can't be edited.

## Adding a question

- Anyone can add a question. It goes to the **Pool**.
- Write it in your own words. Saying why it matters helps others decide whether to take it up.
- Check the suggestions shown while you type: the question may already exist.

## Adopting a question

- To move a question from the Pool to **Active**, someone volunteers as its **steward** and says what will count as an answer (the resolution criteria).
- A question that is meant to stay open (a guiding or rhetorical question) can be adopted as **Standing** instead.
- There can be at most **8** active questions at a time. If the Active lane is full, a question has to be resolved, parked or dropped before another one is adopted.
- The steward keeps the question moving: keeps the link up to date, answers objections and confirms the resolution. Stewardship can be handed over at any time.

## Processes and tools

- A question can be linked to **one** external process: a pull request, a forecast, a poll, an argument map, a proposal.
- Only tools on the **tool list** can be used. Anyone with edit access can add a tool by filling in a short form in the Rules page. No vote is needed.
- A short **framing** note is encouraged: how the process interprets the question, and what it can't tell us.

## When a question is answered

A question is answered when one of its criteria is met, whichever comes first:

- **The process reaches an outcome**, for example the pull request is merged or closed, or the forecast resolves.
- **A date passes**, and we take whatever the process shows at that point.
- **The default rule**: nobody objects within the objection window.
- **The steward attests** that a stated condition was met, for example agreement at a meeting.

Clear outcomes from a process, like a merged pull request, are recorded automatically. Otherwise, the steward confirms the resolution and can add a short statement of what we concluded. A snapshot of the process is saved at that moment.

A resolved question can be reopened if circumstances change.

## The default rule

- When a question uses the default rule, an objection window of **7 days** opens.
- Anyone can object, giving a reason.
- If the window closes with no open objection, the question is resolved.
- If there's an objection, the steward addresses it, or changes the question's criteria. Addressing an objection restarts the window.

## Keeping the register tidy

- Active and standing questions with no activity for **30 days** become **dormant**. Anyone can bring them back.
- Duplicates are dropped and linked to the original.
- Dropped questions stay visible in the archive, with the reason they were dropped.

## Changing these rules

The charter and settings are changed by whoever runs the register, after talking it over with the group. Tools can be added by anyone with edit access.
